### 🔴 问题1: 抢单并发修复方案存在严重BUG

#### 原始代码分析

**文件**: `ErrandOrderServiceImpl.java:172-187`

```java
// 第172-177行:乐观锁更新状态

// 第184-187行:❌ 又执行了一次updateById,破坏原子性!

order.setRunnerFee(runnerFee);
```

#### ErrandOrderMapper.xml:128-137

```xml
<update id="updateStatusWithVersion">
    UPDATE bus_errand_order
    SET status = #{newStatus},
        version = version + 1,
        update_time = NOW()
    WHERE order_id = #{orderId}
      AND status = #{oldStatus}
      AND version = #{version}
      AND del_flag = 0

```

**问题分析**:
1. `updateStatusWithVersion` 只更新 `status`,**没有更新** `runner_id`, `runner_fee`, `platform_fee`
2. 乐观锁更新后,version已经+1
3. 后续 `updateById` 使用旧version更新,会**覆盖**乐观锁的更新,或者失败
4. **这是典型的TOCTOU(Time-Of-Check-Time-Of-Use)漏洞**

#### ❌ 原修复方案的问题

原方案建议:
```java
// 直接使用乐观锁更新,无需先查询
int rows = errandOrderMapper.acceptOrderAtomic(orderId, runnerId, ...);
```

**问题**:
1. ❌ `acceptOrderAtomic` 方法**不存在**,需要新建
2. ❌ 没考虑到需要计算 `runnerFee` 和 `platformFee`
3. ❌ 原代码的 `updateStatusWithVersion` 方法参数不够

```java
@Override
@Transactional(rollbackFor = Exception.class)
public void acceptOrder(Long orderId) {
    Long runnerId = SecurityUtils.getUserId();

    // 1. 检查是否是认证骑手
    BusErrandRunnerEntity runner = runnerMapper.selectByUserId(runnerId);
    if (runner == null || runner.getStatus() != 1) {
        throw new ServiceException("请先完成骑手认证");
    }

    // 2. Redis 分布式锁
    String lockKey = "lock:errand:order:" + orderId;
    boolean locked = false;

    try {
        locked = tryAcquireLock(lockKey, 10, TimeUnit.SECONDS);
        if (!locked) {
            throw new ServiceException("手慢了,订单正在被抢");
        }

        // 3. 查询订单(用于校验和计算费用)
        BusErrandOrderEntity order = this.getById(orderId);
        if (order == null) {
            throw new ServiceException("订单不存在");
        }
        if (!OrderStatus.WAITING.getCode().equals(order.getStatus())) {
            throw new ServiceException("订单已被接单或已取消");
        }
        if (order.getPublisherId().equals(runnerId)) {
            throw new ServiceException("不能接自己发布的订单");
        }
        if (!PayStatus.PAID.getCode().equals(order.getPayStatus())) {
            throw new ServiceException("订单未支付");
        }

        // 4. 计算骑手佣金和平台抽成
        BigDecimal totalFee = order.getTotalFee();
        BigDecimal platformRate = new BigDecimal(platformRateConfig);
        BigDecimal platformFee = totalFee.multiply(platformRate).setScale(2, RoundingMode.HALF_UP);
        BigDecimal runnerFee = totalFee.subtract(platformFee);

        // 5. ✅ 修复:使用原子性抢单操作
        int rows = errandOrderMapper.acceptOrderAtomic(
            orderId,
            runnerId,
            runnerFee,
            platformFee,
            OrderStatus.WAITING.getCode(),
            OrderStatus.ACCEPTED.getCode(),
            order.getVersion()
        );

        if (rows == 0) {
            throw new ServiceException("抢单失败,请重试");
        }

        log.info("订单 {} 被骑手 {} 接单", orderId, runnerId);

    } finally {
        if (locked) {
            releaseLock(lockKey);
        }
    }
}
```

**关键改进**:
1. ✅ 原子性更新:状态、骑手ID、佣金、平台抽成一次更新
2. ✅ 乐观锁保证:version自增,防止并发
3. ✅ SQL层面校验:确保 `pay_status = 1`(已支付)
4. ✅ 移除了冗余的 `updateById` 调用

**前后端联动验证**:

```java
public PageResult<ForumCommentVO> getCommentList(Long postId, Integer pageNum, Integer pageSize) {

    PageHelper.startPage(pageNum, pageSize);
    List<ForumCommentVO> firstLevelComments = commentMapper.selectFirstLevelComments(postId);
    PageInfo<ForumCommentVO> pageInfo = new PageInfo<>(firstLevelComments);
```
